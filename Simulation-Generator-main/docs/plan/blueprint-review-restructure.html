01

Brief summary

Written in ASD-STE100 Simplified Technical English. Short sentences, active voice, one idea per sentence.

The blueprint page shows all sections with the same weight. This is wrong. Some sections are for the teacher. Other sections describe the simulation build. The teacher cannot check the build sections. These sections fill most of the page.

This plan keeps every section. The plan changes the order of the sections. The plan also puts two sections into one closed block.

The plan then makes the model write the blueprint in the same order. The plan also adds two higher audience levels.

The work has five parts:

  1. Change the label Key misconception or difficulty to Where students go wrong.
  2. Move What students should notice up. Put it after What it teaches.
  3. Put What appears on screen and How it should behave into one closed block.
  4. Make LLM call #1 write the fields in the new order. Also make the model match the depth to the audience.
  5. Add Undergraduate and Graduate to the audience list.

The blueprint keeps all of its fields. LLM call #2 receives the same content. A migration is not necessary. The audience column is already free text.

Key code

Three places where a wrong guess would cost a debugging session.

web/components/PlanEditor.tsx — collapse must own the edit state
const BLOCK_SECTIONS: SectionId[] = ['visuals', 'behavior'];

const [detailsOpen, setDetailsOpen] = useState(false);

// Edit inside the block force-opens it, so no form is ever mounted invisibly.
const startEdit = (section: SectionId) => {
  if (BLOCK_SECTIONS.includes(section)) setDetailsOpen(true);
  setEditing(activeEditing === section ? null : section);
};

// Closing the block cancels an edit it would otherwise swallow.
const toggleDetails = () => {
  setDetailsOpen((open) => {
    if (open && activeEditing && BLOCK_SECTIONS.includes(activeEditing)) setEditing(null);
    return !open;
  });
};
backend/src/llm/prompts.py — audience depth, added to PLAN_SYSTEM_PROMPT
## Match the depth to the audience
The audience string names the level. Calibrate to it and never above it.
- School grades: one relationship at a time, whole numbers where possible,
  everyday language, no formal notation.
- Undergraduate: named quantities, standard units, and a stated relationship
  are expected. Two interacting factors are acceptable.
- Graduate: assume the standard result is already known. The simulation must
  probe a limiting case, a failure mode, a boundary condition, or a competing
  regime rather than restate the definition. `misconception` should name a
  subtle or expert-level error, not a beginner one.

Depth changes the concept and the ranges. It never changes the number of
controls, and it never adds lesson material.
backend/src/llm/prompts.py — the reworded purpose section
## Define the purpose
`learning_objective` is the single most important understanding the simulation
must create. `misconception` is shown to the teacher as **“Where students go
wrong.”** Write it as one plain sentence describing what students believe or
where they get stuck — a wrong idea, a confusion, or a step they cannot
picture. Do not use the word “misconception” in the text itself, and do not
address the teacher.

The last snippet is the one that matters most: the field keeps the name misconception, but the prompt must stop assuming a physics-style false belief exists. The binary-search output (“students think binary search is just a faster way to search any list”) is an incomplete idea, not a misconception — the current wording is narrower than the content the model actually produces.

07

Future scope

Assumptions made without asking, and work deliberately left out of this slice.

Assumption: Undergraduate was added alongside Graduate

You asked for a graduate level. Jumping from Grade 12 straight to Graduate leaves an odd gap, and the prompt calibration reads better with a rung between them. Both are one line to remove if you only want Graduate.

Correct during plan review

Should the audience field be free text instead of a select?

audience is already CharField(max_length=64), so a teacher could type “Graduate seminar in numerical methods” and the prompt would use it. A select keeps the demo predictable and keeps the calibration rules matched to known strings. Free text is a better fit for real users, and costs nothing structurally.

Decide with · owner · before v1

Does the closed block stay closed on a re-review?

Assumed yes — always closed on mount, no persistence. A teacher rejecting and regenerating twice may want it to remember. That needs client state we do not have a home for yet, and it is not worth adding before someone asks.

Revisit after the first real teacher session

The two generation defects stay open

Still unfixed, and both change generated output rather than presentation: Number of items ships as 0–100 step 1 default 50 while the blueprint’s own rules demand powers of two (8–128) and an opening state of 16; and Step / Run / Pause / Reset appear in student_actions but have nowhere to live, because _parameter_schema allows only slider | toggle | dropdown | number. Both belong before milestone 3, not inside a UI restructure.
